# Tauri 架构与验收

## 已确定的目标

- 桌面运行时统一使用 Tauri，业务后端统一使用 Rust
- 保留 React、TypeScript、Vite、现有 UI 与播放功能，先验证网络、媒体播放和小窗
- Windows 11、macOS 14+，x64 / ARM64；最低版本与架构须通过真实设备验收
- Rust 业务后端；reqwest + axum + Tokio 负责网络与本地媒体流
- SQLite + SQLx 直接 SQL，通过业务仓储读写，初期单连接池
- 持久化用户数据统一在应用本地数据目录的 `data/data.db`
- 业务数据按表、列组织；可变结构可用 JSON 字段，不把全部数据塞进一个 JSON 对象
- 内存缓存和临时状态不入库；运行日志独立文件管理，不进入用户备份
- 不读取旧架构数据库、Web Storage 或旧 JSON 整库备份；外部源与播放列表格式仍受支持
- 完整备份生成独立 `.db` 快照；恢复校验应用标识、结构版本、完整性，先备份当前库，再用单一事务替换所有业务表数据，失败回滚，成功后重启
- WAL 运行文件不能通过直接复制主 `.db` 备份；使用 SQLite 一致性快照机制
- 优先复用成熟库，避免重复实现与没有业务含义的工具包装

## 代码边界

- `src`：保留前端；`platform` 封装 Tauri 调用，页面不直接执行 SQL
- `src-tauri/src`：启动组装、命令入口、业务模块与基础设施
- `src-tauri/migrations`：保留已发布迁移，后续结构变更只追加迁移
- 开发与打包入口统一使用 Tauri
- 普通请求用 commands，状态通知用 events；任务连续输出按需用 channel
- 媒体内容通过回环 HTTP 流传送，不通过普通 IPC 搬运视频

### 模块维护方式

- 设置页的 `use-source-management` 统一点播与直播源的列表、选择、导入导出、禁用和排序；两类源通过各自的 API 配置接入，点播测速与备用地址切换留在 `use-vod-sources`。
- `basic-player/index.tsx` 持有 ArtPlayer 实例及其完整创建、销毁流程；私有模块分别处理流媒体引擎、调试信息、统计面板、设置菜单和小窗交接。事件与定时器继续随所属播放器释放。
- 电台播放器按音频引擎、节目刷新、详情面板和底部控制栏组织；小窗页面负责组装，播放会话与拖拽缩放分别放在页面私有 hooks 中。
- 源表格、影片目录及网络设置的工具栏、展示组件、分页和弹窗就近拆分，不提升为全局通用组件。
- Rust `sources.rs` 保留公共类型与命令导出，子模块按读写校验、源文件交换、订阅同步及测速划分；地址校验和批量写入由同一仓储实现复用。
- Rust `data_transfer.rs` 保留公共入口，文件对话框、快照恢复、数据清理分别实现；恢复和清理的事务不跨模块拆碎。推荐、电台、点播及订阅共用有界响应读取，业务侧保留各自的超时和大小限制。

## 阶段与验收

1. 基础：Tauri 壳、独立 Vite 配置、新数据库初始化、命令与前端入口
2. 播放验证：直连、系统代理、自定义代理；HLS 清单重写、Range、请求头、重定向、取消、会话释放；点播、IPTV、电台与小窗
3. 业务：设置、订阅、源管理、搜索、目录、收藏、历史；移除前端持久化及数据库缓存
4. 数据管理：完整数据库备份与恢复，替换选择性 JSON 导入导出界面
5. 桌面：日志、窗口、更新、安装分发，维护 Tauri 构建和分发配置

每阶段执行 TypeScript、ESLint 和适用的 Rust 基础检查；不自动执行长时间构建、打包、视觉或播放回归。真实设备播放由开发者验收，未通过阶段 2 不宣称跨平台兼容。

## 跨平台备份与迁移校验

`.db` 快照不绑定操作系统或 CPU 架构；应用版本号也不直接决定兼容性。相同迁移历史可直接导入；已知旧历史先升级副本；高于当前迁移集的历史明确要求升级应用，其他未知或不连续历史拒绝导入。

导入流程：

1. 只读打开原文件，验证应用标识、迁移历史、完整性和外键，用 `VACUUM INTO` 生成独立临时副本。
2. 再验证冻结的副本，修复已知换行差异，执行当前迁移集中尚未应用的迁移；原文件始终不写入。
3. 比较升级后副本与目标的数据表及字段元数据（名称、类型、空值约束、主键、生成列），不比较建表 SQL 原文、字段顺序或索引/触发器文本。只复制业务数据，不导入源库的表定义、索引、触发器和迁移记录。
4. 保存目标库的一致性安全备份，单事务清空并按显式列名写入业务数据，由目标库约束校验；提交前再检查完整性和外键。失败回滚，成功后沿用现有前端重启流程。
5. 成功或失败均关闭专用连接并清理本次临时目录，保留原备份和恢复前安全备份。

历史 Windows 构建的 CRLF 会导致 SQLx 迁移摘要与 LF 构建不同。`.gitattributes` 固定 LF，Rust 构建入口拒绝包含 CR 或 UTF-8 BOM 的迁移，并跟踪迁移目录变化以重新嵌入 SQL。仅首个已发布迁移接受其 CRLF 摘要变体；其他差异仍拒绝。启动修复会先备份，导入修复只写临时副本。

普通启动不保证发现所有手动修改的表、索引或触发器；严格的数据和字段验证集中在导入边界。真实 Windows/macOS 互导与安装升级仍需目标设备验收，不能用本机模拟测试替代。

## 初版数据关联与同步修正

订阅列表按 ID 增量保存，仅删除被移除的订阅，保留其余源、创建时间和同步时间。订阅同步按同一订阅内的规范化主地址匹配已有源，保留源 ID、排序和备注；只写入实际新增或变化的内容，清理订阅中已移除的源。文件导入与订阅同步在事务中一次读取源列表，统一校验最终主地址与备用地址冲突。

界面偏好使用单次 IPC/SQL 读取完整快照，当前窗口在保存完成后刷新，其他窗口通过带来源和作用域的通知刷新。连续通知合并，读取期间的新变更会补读；数据清理通知仍恢复默认值。数据库和文件操作失败时记录经过脱敏的底层错误链，界面保留简短中文提示。

`pnpm test` 统一运行 Rust 测试与前端偏好回归测试；可分别使用 `pnpm test:rust`、`pnpm test:frontend`。前端使用 Node 内置测试运行器、现有 TypeScript 和隔离的 VM 模块，替代 Tauri 依赖，不启动桌面窗口。测试覆盖订阅增删与同步保留引用、批量地址冲突回滚、偏好事件合并与保存失败后的恢复。

## 数据约束与播放记录

八张业务表启用 STRICT，文本主键显式非空，时间与排序值非负，请求头要求 JSON 对象、备用地址要求 JSON 数组，收藏与播放记录的可选原始内容必须是有效 JSON。最近播放使用 `(source_id, vod_id)` 主键，同名作品分别记录；同一视频改名继续更新原记录。恢复进度直接按主键查询，不受列表条数限制，不自动按标题合并跨源进度。

删除源的数据库触发器在同一事务内清理该源的选择及直播频道偏好，覆盖手动删除、订阅同步移除和订阅级联删除；收藏与播放历史保留。应用删除完成后通知各窗口重新加载偏好。完整备份按上述跨平台导入流程验证并升级。
